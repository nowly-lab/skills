# クライアントワーク向けUIデザイン（AIっぽさ除去・情報設計・CV設計）

背骨となる考え方:
1. **AIっぽさは装飾ではなく「判断の欠如」**。決めていない部分が平均・無難な既定値で埋まり、均質に見える。色やフォントの差し替えでは消えない。「意思決定の跡」を残すこと。
2. **見た目より先に「誰に・何を・どの順で」**。情報設計 → 白黒ワイヤー → ビジュアル の順を崩さない。
3. **CVを動かすのは構成・論理・不安の解消**。見た目は最後の後押し。
4. **すべてのデザイン判断を言葉で説明できる状態にする**。これがクライアントワークの価値。

禁止リストを守るだけでは「新しいAIっぽさ」になる（例：紫グラデを避けた結果、クリーム背景＋太い黒枠、くすんだベージュ＋セリフ体＋広い余白、ブルータリズムが次の定番になった。AIっぽさ除去スキルの出力も広まれば型になる）。必ず案件固有の材料（ブランド・読み手・実物の素材）を入れる。方向を決めるときは、同じ業種・同じ読み手向けの実在サイトを集め、共通する型と外れ方を見たうえで、どこに合わせどこを外すかを根拠つきで決める。

---

## Step 1. クライアントを理解する（ヒアリング）
好みより困りごとを聞く。参考サイトは「どこが」好きかを聞く。手元の資料（営業資料・既存サイト・広告）を先に読み込み、不足分だけ質問する。

**事業・目的**
- 事業概要、理念。今いちばん困っていること
- サイト／LPで達成したいこと（集客・採用・ブランディング・販売）
- CVの定義：何をもって成功か。どんな人から、どの手段で（フォーム・電話・LINE・予約）
- CVの「質」の基準（商談化・受注につながるか）
- 新規かリニューアルか、現状の課題、公開日・予算

**読み手（クライアントのお客様）**
- いちばん来てほしいお客様は具体的に誰か（実在の上位顧客の話）
- 申し込み前に感じる不安・抵抗感・「でも…」
- 流入元（広告・検索・SNS・紹介）と、そのときの購買意欲
- お客様がよく使う言葉、よく受ける質問

**競合・強み**
- 本当のライバル（業種が違う相手も含む）
- 他社との違い、それを証明できるもの（数字・実績・声・掲載・資格）

**デザインの方向性**
- 参考サイトの「どこが」「なぜ」好きか。5〜20個を点数化して理由を言語化
- デザイン以外の好み（好きなブランド・車など）、ブランドカラー、避けたい印象

**素材・運用**
- ロゴ・写真（撮影可否）・原稿の有無、必要機能、CMS・更新者、ドメイン・サーバー、解析

出力：「誰に／何を／何のCVのために」を1〜2文で言い切ったブリーフ。

## Step 2. 読み手を解像度高く描く
- ペルソナは具体的な1人（名前・年齢・家族・仕事・流入経路）。
- **ペルソナ × 心理的ハードル** を必ず掛け合わせる。「30代女性向け」は根拠にならない。例：敏感肌で失敗したくない → FVに「パッチテスト済み」「30日返金保証」。
- 本音は匿名Q&A・口コミなど生の声から拾う。
- 見に来る人の目的が複数（顧客と求職者など）なら導線を分ける。

## Step 3. 情報設計（IA）
1. 伝える内容をすべて洗い出し、優先順位をつけ、**主役を1つ**決める。問題は情報量ではなく「全部が同じ強さで主張すること」。
2. セクション順を**読み手の感情の流れ**で並べる。各ブロックの役割は「次を読ませること」。
   - 構成の型（例）：共感 → 理想の未来 → なぜ今必要か → 解決策 → 信頼・実績 → 不安の払拭（FAQ・保証）→ CTA（今行動する理由）
   - 高額・BtoBは「不安との戦い」：煽らず、導入実績・効果・検討プロセスに寄り添う。広告から来た人にいきなり相談を求めず、資料・事例・料金など手前の一歩を用意し、比較検討中の人の質問に答える。料金は「お問い合わせください」で済ませず、目安や決まり方を出す。広告の着地をトップページにせず、買い手の種類（業種・役職）ごとに語りかけるページを用意し、見出しを広告の切り口と合わせる。ただし計測が商談化まで追えていなければ、ページを増やす前にそちらを直す。
   - 短いLPで証拠を厚くする型もある。商材と購買意欲で選ぶ。
3. サイトマップ → **白黒ワイヤー**。ここで視線誘導（Z/F型）・優先順位・余白・重心・CTA位置だけを見る。色や写真は入れない。構成の順番どおりに見た目の強弱がついているかも確かめる（順番を決めても強弱が逆なら伝わらない。整理の問題は配色や装飾では直らない）。
4. **流し読みテスト**：見出しだけ追って話が通じるか。
5. クライアントとワイヤー段階ですり合わせて確定してからビジュアルへ（手戻り防止）。

## Step 4. ビジュアルの判断を先に決める（デザインシステム）
AIに作らせる場合も、人が作る場合も、以下を先に言語化して固定する。
- **感情 → 素材の言葉**：着地した瞬間どう感じてほしいか → 質感の言葉に置き換える（「スポーティ」ではなく「紙にインク」「建築的な石灰岩」）。
- **色に役割**：中立色8〜9割、アクセントは最少でCTAに集中。ブランドカラーをトークン化。状態色（成功・警告・エラーなど）は1色1意味の表にし、その色を使わない場所も書く。色だけで意味を伝えない（エラー欄の赤枠には「何が・どう直すか」の文、選択中のタブには下線や太字、状態にはアイコンや文字を添える）。主ボタンに淡い色を使わない（背景との境界3:1・文字4.5:1を数値で確認）。
- **書体は1ペア**、ブランドの理由で選ぶ。強弱はフォント数ではなくサイズ・太さ（ジャンプ率）で。
- **余白スケール**（8px基準など）。近接で関係を示し、話題の切れ目は大きく空ける。
- **コンポーネントは1種類ずつ**（主ボタン・入力欄・カード）。1画面に主ボタン1つ。主ボタンは対象の内容の直後に置き、離れたフッターに逃がさない。同じ情報を2か所に出さない。
- **案件固有のディテールを1つ**決めてページ全体に通す。非対称などの崩しは理由を説明できるときだけ入れる（毎回入れる決まりにすると、それ自体が型になる）。
- 参考はレイアウトを真似ず「ルール」だけ抽出。参考が**あえて避けていること**も抜き出す。

## Step 5. 制作（AIを使う場合の進め方）
1. ブリーフ・ペルソナ・構成・デザインシステムを先に渡す（PRODUCT.md / DESIGN.md にまとめておく）。
2. 「おしゃれに」「AIっぽさをなくして」とは言わない（別の無難なテンプレに寄るだけ）。ワイヤー・好きなセクションのスクショ・ムードボードなど**見本を見せる**。形容詞ではなく制約（書体1ペア・色数・使わない装飾。禁止は「やめること→代わりに使うもの」の対で）と実際の原稿で渡す。部品は正式な名前（セグメントコントロール、スケルトン表示、下から出るシートなど）で指定し、空・処理中・エラーなどの状態も作るものとして明示する。いきなりコードを書かせず、先に静的なモック画面で合意してから、それに合わせて実装させる。
3. 修正は**範囲を絞って小さく反復**（「余白だけ」「色は変えずコントラストだけ」「文言は変えない」）。
4. 生成後に Step 6 の監査を**別工程として**必ず行う（モデルは平均に戻る）。直しは効く2〜3個に絞る。「もっと良く」のような主観だけの反復は、角丸や薄いコントラストの微調整を繰り返して均質化に戻る。
5. 最後は人の目で違和感を潰し、写真・コピー・ディテールで固有のものにする。

## Step 6. 監査：AIっぽさチェック（見え方 → 直し方）
| 見え方 | 直し方 |
|---|---|
| 紫→青グラデ、グロー、光るエフェクト | 役割を決めた配色。グラデは意味があるときだけ |
| Inter・Geist等の既定書体を全サイズに／流行のイタリックセリフ／明朝＋青紫＋カードの組み合わせ | ブランドの理由で書体1ペアを選び直す |
| 中央寄せヒーロー＋同形カード3枚、ベントグリッド、完全対称 | 優先順位でレイアウト。非対称・意図的な崩し |
| カードの入れ子、角丸カード乱用、すりガラス、上や左に色帯のあるカード | 枠をやめ余白と近接でまとめる。説明できない枠・影は削る |
| 見出し→アイコン→テキストの繰り返し、均等すぎる余白 | 余白に強弱、セクションごとにリズムを変える |
| 毎回のeyebrow、バッジ、ピル、見出しの一語だけ色を変える | 本当に必要な所だけ。強調は意味のある語に限り、サイズ・太さで |
| 絵文字アイコン、どこにでもLucide | 意味があるときだけ、既定以外の統一セット |
| shadcn既定グレー、ブランドカラー不在 | トークン定義してコンポーネントをカスタマイズ |
| ボタンスタイルが何種類もある、ページごとにぶれる | 1種類ずつに統合、余白スケールに揃える |
| 「シームレス」「革新的」「Transform your〜」、BtoBの「AI搭載」「オールインワン」「多くの企業が導入」、意味の取れない詩的なキャッチ（「食卓に、秋のよろこびを。」型） | 対象者・数字・変化、売っているものそのものを書く |
| 和文の不自然な改行・字間・英数字 | 改行を手で直す、字間と欧文のサイズ・書体調整 |
| 写真の光・質感の不一致、均一なツヤ、架空っぽいストック・AI画像 | オリジナル撮影が第一。素材なら「この会社に本当にありそうか」で選ぶ |
| 偽ダッシュボード、何にもつながっていない「稼働中」の緑ランプやカウントアップする数字、実物のないヒーロー | 実際のプロダクト画面・実物写真。状態表示や数字は実データと出典があるときだけ出す |
| 色背景にグレー文字、白背景の薄いグレー文字 | コントラスト確保（4.5:1）。特に電話番号・営業時間・価格・「無料」など、CVに直結する文字から確認する。ダークモードやテーマ切替があるなら両方で測る（一段明るい面の上の文字、ボタン・入力欄の枠、透過ロゴ・OG画像も） |
| 小さいボタン、長すぎる行 | タップ領域は24×24px以上か周りに十分な間隔（WCAG 2.2）。並んだ小アイコン・リンクを特に確認。行長制御、375px幅で確認 |
| 空・読込中・エラー状態がない、理由の分からないグレーアウトの無効ボタン | リスト・フォームごとに3状態を設計。無効にするなら理由をそばに書く（送信ボタンは押せるままにし、押したらエラーで足りない所を示すほうが分かりやすい） |
| 名前のないボタン・ラベルのない入力欄、altのない画像、見えないフォーカス、キーボードで閉じられないモーダル、止められない自動スライダー | 動作が分かるボタン名と、欄の外に常に見えるlabel（プレースホルダーは入力すると消えるのでラベルの代わりにしない）、見えるフォーカス。画像にalt（飾りなら空にする。AIが書いたaltは人が読んで直す）。主要な導線（フォーム送信・モーダル）をTab・Enter・Escだけで通し、フォーカス順と状態の読み上げ（エラー・送信完了）を確かめる。自動で切り替わるスライダー・動きには停止ボタンをつける。Lighthouse等の自動スコアだけで合格にしない |
| 全部が主役 | 最初に読ませるものを1つに絞る |

注意：奇抜さは目的ではない。ターゲットが見慣れたレイアウトを好むなら、それに従う。直す基準は「AIっぽいか」ではなく「読み手が読みやすく、CVに効くか」。枠を外す・色を減らすなどで読みやすさや品質が落ちるなら、AIっぽさが残っても元に戻す。グラスモーフィズムやモーションも「ブランドの理由があれば可」。

## Step 7. 監査：CVチェック
アプリ画面ではLP向けの項目より、OSの慣習と状態ごと（空・処理中・エラー・無効）の見え方を優先して見る。
- [ ] FVだけで「誰向けか／何が得られるか／次に何をするか」が分かる（5〜7秒テスト）
- [ ] 見出しが具体的（対象者・数字・変化）。常套句なし
- [ ] 広告・流入元の言葉とFVの言葉が一致（メッセージマッチ）。1ページ1オファー。Google広告のAI Max（最終ページURL拡張）は新規検索キャンペーンで既定オンになりうるので、広告のクリックが意図したLPに着地しているかを配信設定と着地URLのレポートで確かめる
- [ ] 社会的証明（評価・件数・ロゴ・掲載）が上部にある。実名・ロゴ・出典で確かめられるものに限る。ロゴのない「10,000社が信頼」や誰か分からない推薦文は、かえってAIっぽく見え信用を落とす
- [ ] CTAは1種類、2〜3回繰り返し。文言は製品名ではなく得られる結果
- [ ] CTA付近にマイクロコピー・保証（所要時間、費用が発生しない、キャンセル可、返金）。「送信」で済ませず、押した後に何が起きるかを書く
- [ ] ペルソナの不安を列挙し、それぞれにページ内で答えている（FAQ・保証・「おすすめしない人」）
- [ ] 機能ではなくベネフィット（使った後の変化）を書いている
- [ ] 感情の流れが途切れない
- [ ] CTA周りに余計なバナー・リンクがない（足すより引く）
- [ ] フォームは今必要な項目だけ（リードの質を絞る質問は1問まで）。住所など「とりあえず必須」をやめ、BtoBで項目を足すか削るかは、営業が後で使うかと離脱の兼ね合いを先に決めてから組む。項目に合うキーボード（電話は数字、メールは@）、全角半角の自動変換。個人情報への警戒が強いので、何に使うか（営業電話をしない等）を入力欄の近くに一言書く。空のまま送信して、エラーの場所が分かり、フォーカスがそこへ移るか試す
- [ ] 確認画面・完了画面も設計している：修正しても入力値が残る、送信直前の迷いに一言で答える、「いつ・誰から連絡が来るか」を送信ボタンの手前と完了画面の両方に書き、完了後は次の一歩（日程予約など）を示す。公開前にスマホから実際に1件送り、完了表示・自動返信・担当者の受信箱（迷惑メールも）まで届くか、通知先が今の担当者かを確かめる（届かないフォームはどんな設計より先にCVを失う）
- [ ] 375px幅で文字・行間・ボタンに問題なし。表示が速い
- [ ] 計測できる状態で、どの段階（CTR／CVR／フォーム）で落ちているか、PCとスマホに分けて特定できる。成果は手前のCV数（資料請求数・CPL）ではなく、商談化・申込まで追って判断する

## Step 8. クライアントへの提案
- 各判断を「読み手の誰の、どの不安／目的に対して、なぜこうしたか」で説明する。
- 必要なら複数案を出し、判断軸（ターゲット・目的・競合）を添えて一緒に選ぶ。
- 「それ本当に必要ですか？」と言える発注者目線を持つ。
- 公開後は指標の階層で落ちている箇所を特定し、ヒートマップ等で仮説を立てて1つずつ改善する。AIによる監査・改善案はもっともらしいだけのことがあるので仮説として扱い、ABテストなどの実測と食い違えば実測を優先する。施策の前後比較だけで効いたと決めない（配信先の相手や時期が変わっていることがある）。できれば変えなかった群と比べる。

## 出力フォーマット（レビュー依頼時）
1. 一言の総評（誰に何を伝えるページとして機能しているか）
2. 重大度順の問題点（情報設計 → CV → AIっぽさ → 細部）と、それぞれの具体的な直し方
3. すぐ直せる改善トップ3
4. 修正後の再レビューでは、before/afterと状態ごとの見え方を比べ、直したことで出た退行も探す
